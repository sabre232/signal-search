# 意图拆解 + 子路由分配 方法论（Signal-Search）

> 本文档是 `plan.py`（§5.7 / §6.5）的实现依据，也是 §13 **M08–M10** 验收对照源。蓝图 §5.7 引用本文件。
> 原则（D10）：意图拆解必须有方法论，不是拍脑袋拆；子路由按"正交维度"分配。

---

## A. 先理解意图，再拆解

每轮先把 query 解析为结构化：
- **核心目标** / **约束条件**（如"带3岁娃和60岁父母去三亚5天、预算1万、海景房" → 核心=做攻略，约束=老人小孩/预算/海景/慢节奏）
- **关键实体**（NER 抽取专名/术语）、**隐性约束**（未明说但隐含的条件）、**歧义点**（多义词标注）
- 然后才决定拆成哪些子查询。

`classify_intent(query) -> {intent, confidence, granularity, implicit_needs[]}`：
- `intent ∈ {fact, compare, howto, why, research, latest, verify}`
- `confidence < 0.6` → `need_clarify=True`，SKILL.md 向用户澄清（最多 1 轮）（M08）

## B. 四种拆解范式（按查询形态选，不要一刀切）

### 1. 成分/组合型（entity × dimension）→ fan-out 并行
独立叶子，并行执行后聚合。叶子必须"无需互相等待即可单独回答"。
- 例："对比 A/B/C 三家在 GDPR/HIPAA/SOC2 的隐私差异" → 3×3=9 个独立叶子，并行；聚合带 **per-leaf 溯源**（M09）。
- 验收锚点：拆成 9 独立叶子 + 并行 + 溯源，无依赖。

### 2. 多跳依赖型 → 有序串行
前一跳结果作后一跳检索条件。
- 例："入职3年研发岗已休5天年假、再请10天事假是否合规" → 先查年假天数 → 再查事假上限 → 再查是否关联（M10）。
- 验收锚点：产出有序依赖链（年假→事假→合规）。

### 3. 实体锚定型（UniRAG, EMNLP 2025）
先 NER 抽实体，再让 LLM 围绕每个实体生成**单跳聚焦子查询**，保证语义相关且不重不漏。

### 4. 迭代重写型（Omni-RAG / SIGIR LiveRAG 2025）
先 rewrite 清噪（修拼写/歧义），再 decompose 成结构化 JSON 子查询；若当前轮无法给高置信答案，则基于推理历史**重写 query 再检索一轮**（缺口驱动，见 §5.10 SEA）。

## C. 子路由分配规则（多智能体编排 2026 实证）

- **按"方面/维度"分解，不要按"步骤"分解**：研究型任务识别正交分析维度（市场/技术/竞争），每维度一个 worker；按步骤分解会制造顺序依赖、摧毁并行性。
- **限制嵌套深度**：叶子 worker 不再派生 worker（至多一层嵌套），避免成本组合爆炸。
- **显式交付物**：每个子查询/worker 被告知"必须返回的确切工件"（如"一段总结 + 三条引用 + 来源 URL"），便于聚合即时验证、避免静默盲区。
- **模型路由**：拆解/重写用弱模型（快、省），综合/研判用强模型；实测降本 35–50% 且不损关键质量。
- **并行边界**：依赖关系用有向图表达——独立叶子并行（端到端延迟≈最慢叶子+协调开销），有依赖串行；聚合时**解决冲突并标注每条结论来自哪个叶子**（溯源）。
- **宽度上限**：L2 默认 ≤8 叶子，L3 ≤20 叶子（§6 / tier-policy.md）。

---

## D. 失败模式（必须规避）

| 失败 | 后果 | 对策 |
|------|------|------|
| 误拆解 | 静默丢掉原问题某维度 | 聚合前做**维度覆盖自检**：断言原问题所有维度均被某叶子覆盖（防静默漏维） |
| 过度 fan-out | 叶子过多成本爆炸 | 设宽度上限（L2≤8, L3≤20） |
| 聚合丢细节 | 合并时抹平叶子差异 | 聚合 prompt 强制"保留 per-leaf 溯源与冲突" |

## E. few-shot 模板（写入 plan.py 系统提示）

```
输入: 对比 A/B/C 在 GDPR/HIPAA/SOC2 的隐私差异
输出(JSON):
{
  "intent": "compare",
  "leaves": [
    {"q":"A 的 GDPR 合规要点", "depends_on":[], "dimension":"A/GDPR"},
    {"q":"A 的 HIPAA 合规要点", "depends_on":[], "dimension":"A/HIPAA"},
    ... (共 9 个, 无 depends_on, 可并行)
  ],
  "coverage_check": "原问题维度 {A,B,C}×{GDPR,HIPAA,SOC2} 全部覆盖"
}
```

```
输入: 入职3年已休5天年假再请10天事假是否合规
输出(JSON):
{
  "intent": "verify",
  "leaves": [
    {"q":"研发岗法定年假天数(入职3年)", "depends_on":[], "dimension":"年假基数"},
    {"q":"事假上限与年假已休是否关联扣减", "depends_on":["年假基数"], "dimension":"事假规则"},
    {"q":"该情形合规结论", "depends_on":["年假基数","事假规则"], "dimension":"结论"}
  ]
}
```
