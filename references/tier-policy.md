# 档位策略 L0–L3 详细规范（Signal-Search）

> 本文档是 `route.py`（§5.6）与 `stop.py`（§5.10）的实现依据，也是 SKILL.md 档位块的详版。蓝图 §6 / §8 引用本文件。
> 读者：构建者（实现 `route.py` / `stop.py`）+ 验收人（对照 M06/M07/M27/M42/M43）。

---

## 1. 四档总览

| 档位 | 触发场景 | 默认预算(token) | 用源数 | 检索动作 | 停止条件（见 §4） |
|------|----------|----------------|--------|----------|------------------|
| **L0 速查** | 答案唯一可验证（日期/语法/命令/定义/单位换算） | 2,000 | 1 | 不检索或单次；**禁思维链** | 一次命中即停；"无需检索"直接答 |
| **L1 单点** | 明确事实（谁/多少/是什么） | 8,000 | 1–3 | 1–2 引擎单次 + 1 次根因反问 | 1–2 源一致即停 |
| **L2 诊断/方案** | 对比/为什么/怎么选/风险/评估 | 30,000 | 3–8 | 多源对比 + 聚合 + 验证 | 连续 2 轮无新信息 / 缺口闭合 |
| **L3 研究** | 调研/方案/前沿/学术 | 100,000+ | ≤20 | planner→并行 crawler→publisher（§3）+ 早停 | SEA 缺口驱动；预算软上限兜底 |

> **默认档位 = L1**。用户显式覆盖：`/signal L3 调研 X`、`/signal L2 对比 A B`。

## 2. 触发规则（启发式，命中即取最高档）

`classify_tier(query, constraints) -> (tier, reason)`：

| 命中词 / 特征 | 升档 |
|---------------|------|
| "最新/今天/实时/排名/对比/为什么/怎么选/调研/分析/方案/风险/前沿/评测" | → L2（含研究性词再 → L3） |
| "调研/研究/综述/学术/论文/怎么做一套/系统性" | → L3 |
| "是什么/谁/多少/定义/日期/某语法/怎么读文件/怎么装/某命令/单位换算" 且答案唯一可验证 | → L0 |
| 默认（明确事实、单点查询） | → L1 |

- 多词冲突时取**最高**档（如"对比 A/B 的最新方案" → L3）。
- `constraints.required_tier` 直接采用，不跑启发式；reason 标注"用户指定"。

**验收锚点（M06）**：
- "2026-08-07 是星期几" → L0
- "珠峰海拔多少" → L1
- "对比 A 与 B 的隐私差异" → L2
- "调研 agentic search 前沿" → L3
- `/signal L3 X` → 返回 L3 + reason"用户指定"（M07）

## 3. L3 并行 crawler 策略（B3，仅 L3）

`parallel.py`（§5.15）显式三段：

1. **planner**：`planner(query)` 产出子问题树（outline），叶子带 per-leaf 交付物定义（"一段总结 + 三条引用 + 来源 URL"）。
2. **execution（并行）**：`ThreadPoolExecutor(max_workers=8)` 并发爬各叶子；单 leaf 失败不影响其它（复用 B5 失败隔离）。
3. **publisher**：多源都提到的内容权重更高（共识加权，与 SBA 呼应）；冲突按 §5.12 显式标注。

**验收锚点（M34）**：≥3 子问题真正并行（墙钟 < 串行估算 70%）；publisher 输出多源一致结论置信度高于单源；单 leaf 失败仍生成报告。

## 4. 自适应停止（模式感知，§5.10 / §8）

停止判据**因档位而不同**，杜绝"少抓"一刀切误伤调研/论文场景。

### 4.1 L0/L1 = 缩范围模式（reduce-scope）
- 预算即停：token 软上限到达即停，标 `exhausted=False`（可能未穷尽，但速查/单点本就不追求穷尽）。
- L0：一次命中即停；"无需检索"直接答。
- L1：1–2 源一致即停。

### 4.2 L2/L3 = 保覆盖模式（fix-scope-and-quality）
以**覆盖饱和度**停止，而非预算停止。满足任一即停：
1. **覆盖率清单闭合**——原问题拆出的所有子问题均已充分回答（coverage checklist，最可靠法）。
2. **引用收敛**——同一批核心源在多次独立查询中重复出现（"核心材料已找到"）。
3. **单源饱和度**——每个被引源已跑 ≥min 轮且新论文/新引用低于阈值（单源只查一次不得判饱和）。
4. **缺口批评家判"无缺口"**——LLM 判信息足够。

预算仅作**兜底**：到达预算但未饱和时，**必须显式标 `exhausted=True` 且 `trace.stop_reason` 写明"因预算截断、覆盖可能不完整"**——**绝不静默截断**。

### 4.3 通用停止信号
- 连续两轮检索去重后无新增 URL/事实 → 停（TASR 可操作化，各档通用）。
- "决定不检索"是一等能力：LLM 判证据足够即停，不强制再搜。

**验收锚点**：
- M27：连续重复查询第 2 轮无新信息即停，`reason` 含"无新信息"。
- M42（L2/L3 红线）：预算先到但覆盖未饱和 → `exhausted=True` + `stop_reason` 说明未穷尽，不标完整。
- M43：调研任务子问题全答 / 引用收敛 / 单源饱和 其一即停。

---

## 5. 红线（验收不及格项）

- 每次停止必写 `trace.stop_reason`（搜了几轮、为何停）。
- **静默截断**（让用户误以为覆盖完整）= 验收不及格（M42）。
- L3 不允许单线程串行爬（必须走 §3 并行）。
